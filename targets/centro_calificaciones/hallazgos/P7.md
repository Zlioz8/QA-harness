## Qué está pasando

El manual `docs/Manual despliegue CENTRO COMPLETO.md` (rama `lmsActividad`, commit 22/08) describe un
entorno que **no es el destino real**, y su §5 trae parches que **no compilan**:

- **Servidor web:** el manual manda Apache (`§2.4`: alias, `mod_rewrite`, `mod_proxy`) y el propio
  `Report_criteria` histórico reclama módulos de Apache faltantes. El servidor real
  (`zajunavideo5.com`) sirve las apps con **nginx/1.24.0** (cabecera `Server: nginx`). El manual
  describe la máquina del autor, no el ambiente de despliegue — mismo eje que se vio en #7 (D1).
- **PHP:** el manual exige PHP **8.2**; el core de esta máquina corre PHP **8.1.34**. Las apps
  funcionan igual (se probó), pero el requisito no describe el destino.
- **Parches del §5 rotos:** los bloques que el manual manda pegar en el core contienen
  `$external_gradebook_url = new_url;` (constante `new_url` inexistente → *undefined constant*) y
  `html_writer::link($new_url, $coursenamelink;)` (error de sintaxis, `;` dentro de los argumentos);
  y el bloque §5.2 completo va comentado con `/* … */`, así que la redirección que documenta ni
  siquiera se ejecuta. Verificado leyendo el manual; aplicarlos literalmente rompería el core
  compartido.

## Por qué es un riesgo

Un manual de despliegue es un contrato: si describe otra máquina, el operador que lo siga al pie
obtiene un despliegue distinto del que el equipo valida, y no sabe distinguir un fallo real de una
divergencia esperada. Aquí la divergencia tiene además consecuencias de seguridad: seguir el manual
(Apache sin regla de ficheros ocultos) reintroduce P5 (.env/.git servibles), que el servidor real
evita solo porque usa nginx. Y unos parches que no compilan, pegados en un core compartido por 5
proyectos, son un incidente esperando a ocurrir. Fundamentado en `riesgos/P7.md` (proceso/CWE-1059;
no encaja en STRIDE ni tiene vector CVSS: es un defecto de documentación con impacto de seguridad).

## Recomendación de remediación

Alinear el manual con el **ambiente de destino** (nginx, la versión de PHP real, rutas bajo el core),
o parametrizarlo declarando explícitamente qué asume. Corregir los parches del §5 para que compilen
(`new_url` → `$new_url`, sintaxis de `html_writer::link`) y, mejor, sustituir el parcheo manual del
core por el plugin de Moodle (ver P4). Incluir en el manual el bloqueo de ficheros ocultos como paso
obligatorio (P5).

## Verificación

El manual nombra el servidor web y la versión de PHP reales del destino; y los bloques de código del
§5, copiados literalmente, pasan `php -l` sin errores de sintaxis ni constantes indefinidas.
