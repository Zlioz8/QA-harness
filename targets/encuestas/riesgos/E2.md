# E2 · El despliegue no arranca: el schema `Produc` no se crea

> Severidad de la auditoría: **Alta**. Documento probatorio y formativo, no una PoC.

## Dónde vive

En la orquestación de arranque del despliegue de producción: `deploy/postgres/10-search-path.sql`
(que se monta en `/docker-entrypoint-initdb.d/`) y las migraciones de Laravel bajo
`database/migrations/` (no-squashed, empiezan en `2024_01_01`). El `.env` de producción declara
`DB_SCHEMA=Produc`.

## Por qué es tangible

- **Actor**: no hay adversario — es un fallo de disponibilidad que se dispara solo, en el primer
  despliegue desde cero de cualquiera que siga el manual al pie.
- **Cadena, reproducida en esta auditoría (2026-08-24):**
  1. `docker compose -f deploy/docker-compose.prod.yml up -d --build` sobre una BD vacía.
  2. El servicio `migrate` muere: `SQLSTATE[3F000]: Invalid schema name: no schema has been selected
     to create in (SQL: create table "migrations" ...)`.
  3. Causa: `10-search-path.sql` hace `ALTER ROLE encuestas SET search_path TO "Produc"` pero
     **nunca ejecuta `CREATE SCHEMA "Produc"`**. Como las migraciones no son un squash, `migrate`
     intenta crear la tabla `migrations` en un schema inexistente.
  4. `app` y `worker` no arrancan (`depends_on: service_completed_successfully`): fail-closed, pero
     la aplicación queda CAÍDA.
  5. Fix verificado: `CREATE SCHEMA IF NOT EXISTS "Produc" AUTHORIZATION encuestas;` → las
     migraciones completan y la API responde 200.

El riesgo es tangible porque el manual, seguido literalmente, produce un sistema no operativo.

## OWASP

- **Top 10 2021 — A05:2021 Security Misconfiguration**: la categoría cubre despliegues incompletos o
  con pasos de configuración implícitos que rompen el sistema. Un manual que no crea un objeto de
  BD del que depende es configuración defectuosa.
- **ASVS v4.0 — 14.1.1** (procesos de build y despliegue documentados y automatizados, reproducibles
  sin pasos manuales no descritos): incumplido — falta un paso.

## MITRE

- **CWE-909: Missing Initialization of Resource** — un recurso (el schema) del que el sistema
  depende no se inicializa antes de usarse.
- **CWE-665: Improper Initialization** (relacionada). No aplica ATT&CK: no hay adversario.

## STRIDE

**Denial of Service**: el efecto es la indisponibilidad del sistema tras el despliegue. No hay
componente de confidencialidad o integridad — es puramente disponibilidad.

## CVSS

**CVSS 3.1: 0.0 en la escala de ATAQUE** (no es explotable por un adversario). Se documenta con una
**severidad OPERATIVA Alta**: la métrica CVSS mide explotabilidad, no impacto de disponibilidad por
error propio, así que aquí la severidad la fija el laboratorio por su efecto (arranque roto), no un
vector CVSS. Es una distinción importante para el equipo: no todo hallazgo Alto tiene vector CVSS.

## ISO/IEC 27001

- **A.8.32 Gestión de cambios** — un cambio (el despliegue) no se puede aplicar de forma controlada
  y reproducible porque le falta un paso.
- **A.5.37 Procedimientos operativos documentados** — el procedimiento de despliegue está
  incompleto en su punto crítico.

Para certificación, toca A.5.37: los procedimientos operativos deben estar documentados y ser
ejecutables por alguien que no escribió el sistema.

## Qué debe asimilar el equipo

`search_path` apuntando a un schema NO crea ese schema — son dos operaciones distintas en
PostgreSQL. Y un manual de despliegue vale exactamente lo que vale ejecutado desde cero en una
máquina limpia: probarlo en un entorno que YA tiene el schema (porque se creó a mano alguna vez)
esconde el fallo. La disciplina: validar el despliegue contra una BD vacía, no contra la de
desarrollo.

## Criterio de cierre

Añadido `CREATE SCHEMA IF NOT EXISTS "Produc" AUTHORIZATION encuestas;` al `10-search-path.sql`, un
`up -d --build` sobre una BD vacía debe terminar con `migrate` en código 0 y `app` respondiendo 200
en `/api/contact-info`, sin ninguna intervención manual.
