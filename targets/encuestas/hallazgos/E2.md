## Qué está pasando

Siguiendo `deploy/README-DESPLIEGUE.md` al pie de la letra, un despliegue desde cero **NO arranca**.
El servicio `migrate` muere con `SQLSTATE[3F000]: Invalid schema name: no schema has been selected
to create in`. Causa: `deploy/postgres/10-search-path.sql` fija `ALTER ROLE encuestas SET
search_path TO "Produc"` pero **nunca crea el schema `Produc`**, y como las migraciones no son un
squash (empiezan en `2024_01_01`), `migrate` intenta crear la tabla `migrations` en un schema que
no existe.

## Por qué es un riesgo

Es el punto más crítico del manual —el arranque— y está roto. Quien despliegue desde cero se topa
con la API caída y un error que no nombra la causa (el schema que falta), lo que convierte un
arreglo de una línea en horas de diagnóstico. El servicio `migrate` sale con código != 0 y `app`/
`worker` no arrancan (el fail-closed funciona), así que el fallo es visible, pero opaco.

## Recomendación de remediación

Añadir una línea al `deploy/postgres/10-search-path.sql`:
`CREATE SCHEMA IF NOT EXISTS "Produc" AUTHORIZATION encuestas;` ANTES del `ALTER ROLE`. Aplicado a
mano en el despliegue de validación; tras ello las migraciones completaron todas.

## Verificación

`docker compose -f deploy/docker-compose.prod.yml up -d --build` sobre una BD vacía debe terminar
con el servicio `migrate` en código 0 y `app` respondiendo 200 en `/api/contact-info`.
