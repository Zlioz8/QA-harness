## Qué está pasando

Dos fricciones alrededor de PgBouncer que el manual no cubre. **(a)** El `userlist.txt` que pide el
README §1 necesita el hash SCRAM del rol `encuestas`, que solo existe DESPUÉS de que el contenedor
`postgres` cree el rol al primer arranque — pero `pgbouncer` monta ese fichero al arrancar y
`depends_on: postgres healthy`. Es una dependencia circular no documentada. **(b)** El `.gitignore`
NO cubre `deploy/pgbouncer/userlist.txt` (solo `.env*`), pese a que el README dice «NO versionar el
real».

## Por qué es un riesgo

(a) hace que un despliegue desde cero se atasque hasta que alguien deduzca el orden correcto
(levantar postgres solo → leer `pg_authid.rolpassword` → escribir el fichero → levantar el resto).
(b) deja la puerta abierta a que alguien versione el hash SCRAM de la BD de producción.

## Recomendación de remediación

Documentar en el README el orden de arranque para generar `userlist.txt`, o automatizarlo con un
init-container. Y añadir `deploy/pgbouncer/userlist.txt` al `.gitignore`.

## Verificación

Un despliegue desde cero siguiendo el README actualizado debe levantar sin pasos manuales no
descritos. `git check-ignore deploy/pgbouncer/userlist.txt` debe confirmarlo ignorado.
