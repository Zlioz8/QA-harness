## Qué está pasando

Dos migraciones del repositorio **no aplican sobre una base de datos limpia**. Reproducido en
aislamiento, creando una base vacía y aplicando solo el archivo en cuestión:

```
psql:/migrations/006_josso_event.sql:39: ERROR:  column "num_documento" of relation
                                                "josso_event" does not exist
psql:/migrations/004_log_histories_indexes.sql:9: ERROR:  schema "LOG" does not exist
```

En `006` el orden es el problema: el `CREATE TABLE` (línea 4) no incluye `num_documento` ni
`tipo_documento`; el `INSERT` (línea 20) las nombra como sus dos primeras columnas; y el
`ALTER TABLE … ADD COLUMN IF NOT EXISTS` que las añade está **quince líneas después** del INSERT.
El propio comentario del archivo lo delata: *«si la tabla ya existía sin ellas»* — se probó
contra una base que ya tenía la tabla, nunca desde cero.

## Por qué es un riesgo

El esquema no se puede construir desde el repositorio. Un despliegue nuevo, un entorno de
pruebas o una recuperación ante desastre arrancan con la base incompleta, y el síntoma no señala
la causa: la aplicación devuelve un 500 genérico (ver §3.12).

Es la misma clase de defecto que el `DEPLOY.md` ya documenta para la migración `008`, lo que
sugiere que el problema no es un descuido puntual sino que **las migraciones no se prueban desde
cero**.

## Recomendación de remediación

- *Explicación:* una migración tiene que ser aplicable sobre una base vacía y sobre una ya
  existente. El `ALTER` idempotente que ya está escrito es correcto; solo está en el sitio
  equivocado.
- *Orientación:* mover en `006` el bloque `ALTER TABLE … ADD COLUMN IF NOT EXISTS` **antes** del
  `INSERT`. En `004`, crear el esquema `LOG` (o condicionar los índices a que exista). Y añadir
  al ciclo de trabajo una comprobación que aplique la cadena completa sobre una base recién
  creada — es lo que habría detectado esto y el caso de `008`.

## Verificación

```bash
createdb prueba_esquema
psql -d prueba_esquema -c 'CREATE SCHEMA "ADI"; CREATE SCHEMA "INTEGRACION";'
for m in database/migrations/00*.sql; do psql -v ON_ERROR_STOP=1 -d prueba_esquema -f "$m" || break; done
```
Debe completar las ocho migraciones sin un solo error.
