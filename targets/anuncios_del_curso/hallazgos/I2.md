## Qué está pasando

`mod_imagecarousel_pluginfile()` (`lib.php:437`) sirve ficheros con dos defectos de control:

1. **Fallback por nombre a través de imágenes distintas.** Si no encuentra el fichero por su
   `itemid`, busca el mismo NOMBRE en el área de archivos de esa imagen y, si tampoco, itera por
   **todas las imágenes del carrusel** hasta encontrar un fichero con ese nombre (`break 2`,
   `lib.php:507-521`). El vínculo `itemid ↔ imagen` que la URL declara deja de respetarse: se puede
   recibir el fichero de OTRA imagen del mismo carrusel pidiéndolo por un `itemid` cualquiera.
2. **No comprueba la visibilidad.** La función valida contexto, `require_login` y que la imagen
   exista, pero nunca mira `$image->visible` ni el toggle global. Una imagen ocultada seguiría
   sirviéndose por esta vía.

## Por qué es un riesgo

Es una guarda de autorización rota por diseño: el control «este fichero pertenece a esta imagen y
esta imagen está visible» no se aplica. Hoy el impacto real es BAJO porque el flujo de subida
almacena las imágenes como base64 en la base (hallazgo I3) y no en el file storage, de modo que
`pluginfile.php` no tiene ficheros que servir (verificado en vivo: 404 con sesión). Es, por tanto,
una **guarda rota latente**: en cuanto una versión futura vuelva a usar el file storage de Moodle
—lo natural para un plugin de imágenes— el fallback serviría imágenes ocultas o cruzadas entre
instancias. El código de control ya está mal escrito; sólo espera datos que lo activen.

## Recomendación de remediación

Servir estrictamente el fichero identificado por `itemid` + nombre + contexto; eliminar el bucle
que busca «por todas las imágenes del carrusel». Añadir la comprobación de `$image->visible` (y del
toggle global) con la misma lógica que `carousel_content.php`, negando con 404 si la imagen está
oculta y el usuario no tiene `manageitems`. Migrar el almacenamiento al file storage (I3) hace esta
función necesaria y correcta a la vez.

## Verificación

Con imágenes en el file storage: pedir `pluginfile.php/<ctx>/mod_imagecarousel/images/<itemidA>/<nombreDeB>`
debe devolver 404, no el fichero de B; y pedir el de una imagen oculta como student debe devolver
404. Revisión de código: `mod_imagecarousel_pluginfile` sin el bucle `break 2` y con chequeo de visibilidad.
