# P6 · El DEPLOY.md documenta el entorno del autor (Apache/HTTP/5433), no el destino

> Severidad de la auditoría: **Media**. Este documento PRUEBA que el riesgo es tangible y lo
> fundamenta en marcos reconocidos. Es un hallazgo de PROCESO, formativo.

## Dónde vive

En el propio `DEPLOY.md` (commit `9674bda`, entregado el 2026-08-25). El documento describe, con
precisión, el «entorno de referencia» que el desarrollador inspeccionó en SU máquina:

- §2, §11: **Apache 2.4.58 + `mod_php`**, «el reverse proxy real de este proyecto es Apache».
- §2, §21: **sin HTTPS** — «HTTPS: no aplica», «no se documentan certificados».
- §3, §8.1: PostgreSQL en el puerto **5433**.
- §5, §6.1: `$CFG->wwwroot = http://localhost/zajuna`.
- §3, §13: PHP **8.2.32** como requisito de la tabla de versiones.

## Por qué es tangible

Cotejado contra ESTE ambiente (despliegue de esta auditoría, 2026-08-25) y contra producción
(`zajunavideo.com`), las cinco afirmaciones difieren del destino real:

| El manual dice | Este ambiente | zajunavideo.com |
|---|---|---|
| Apache 2.4.58 + mod_php | **nginx/1.24.0 + php-fpm 8.1** (cabecera `Server: nginx`) | Apache/2.4.52 |
| «HTTPS: no aplica» | **HTTPS obligatorio** (:80 → 301 → :443) | HTTPS |
| PostgreSQL 5433 | **5432** | — |
| `http://localhost/zajuna` | `https://nginx.zajuna.com/zajuna` | `https://zajunavideo.com/zajuna` |
| PHP 8.2.32 | **8.1.34** (los 46 ficheros pasan `php -l`) | — |

- **El smoke test del propio manual falla por esto.** §16.1 dice: «Debe responder `303 See Other`
  con `Server: Apache/...`». En este ambiente responde `Server: nginx`. Un operador que siga el paso
  al pie no sabe si el `nginx` es un problema o no — el manual no contempla su propio destino.
- **No impide el despliegue** (el plugin es PHP servido por el web server, le da igual cuál), pero
  **desorienta**: quien despliegue en el ambiente real encuentra un servidor, un protocolo y un
  puerto distintos de los documentados, y no tiene forma de saber cuál es el correcto.
- **El PHP 8.2 es un requisito FALSO por exceso:** el plugin corre en 8.1 (verificado: `php -l` en
  los 46 ficheros y las 11 páginas responden 200). Documentar 8.2 como mínimo puede bloquear
  despliegues válidos.

## OWASP

- No es una vulnerabilidad técnica: es un fallo de **proceso/SDLC**. Encaja en el espíritu de
  **OWASP SAMM — Operations / Environment Management**: la documentación de despliegue debe
  describir el entorno de PRODUCCIÓN, no el de desarrollo.

## MITRE

- **CWE-1059: Insufficient Technical Documentation** — la documentación no corresponde al sistema
  real.
- **CWE-1053: Missing Documentation for Design** (parcial): el destino de despliegue no está
  documentado; lo que se documenta es otro entorno.
- Sin ATT&CK: no hay adversario. Es proceso.

## STRIDE

No encaja en STRIDE (que modela amenazas de un atacante). Es un riesgo de **proceso**: la deriva
entre la documentación y el sistema real. Forzar una casilla enseñaría un mapeo falso.

## CVSS

**n/a — sin vector.** No es explotable. La severidad Media viene del impacto operativo (despliegues
desorientados, un smoke test que falla por diseño), no de un ataque.

## ISO/IEC 27001

- **A.5.37 Procedimientos operativos documentados** — el procedimiento debe reflejar el entorno
  real de operación.
- **A.8.32 Gestión de cambios** — la documentación debe mantenerse alineada con el entorno de
  destino.

## Qué debe asimilar el equipo

Un manual de despliegue describe el DESTINO, no la máquina donde se escribió. La honestidad del
documento (declara lo que inspeccionó, con comandos) es una virtud —y hay que reconocérsela— pero
inspeccionó el entorno equivocado. La corrección es barata: parametrizar el manual («el web server
puede ser Apache o nginx; en Zajuna es nginx bajo `/zajuna` con HTTPS»), o escribirlo contra el
ambiente de integración real. Un smoke test que espera `Apache` donde hay `nginx` no verifica nada.

## Criterio de cierre

El DEPLOY.md describe el ambiente de destino (nginx/php-fpm, HTTPS, `/zajuna`, PostgreSQL 5432) o
declara explícitamente que el web server/protocolo/puerto son variables y cuáles son en producción;
y el smoke test §16 no fija `Server: Apache`. Verificable leyendo el manual contra la cabecera real.
